01 / OVERVIEW

תקציר מנהלים

מטרת הפרויקט: בניית תשתית פנימית שאוספת לידים מכל ערוצי השיווק של דטוויז למקום אחד, מסננת, מתייגת, ומזרימה אותם אוטומטית לקומיגו. כולל דשבורד פנימי לניטור, סטטיסטיקות וניהול.

הבעיה והפתרון

המצב כיום
  • לידים מהאתר נשלחים למייל ולא מסונכרנים אוטומטית לקומיגו
  • הזנה ידנית גוזלת זמן ויוצרת איחורים בתגובה ללקוח
  • אין נראות מרכזית של כל הלידים הנכנסים
  • אין מדידה של ביצועי כל ערוץ שיווק
  • סכנה אמיתית של איבוד לידים בהמולת היומיום
אחרי ההטמעה
  • קליטת לידים אוטומטית מכל מקור תוך שניות
  • תיוג, סינון והעשרה אוטומטיים לכל ליד
  • סנכרון מיידי לקומיגו ללא מגע יד אדם
  • דשבורד מרכזי לצפייה ולניתוח כל הלידים
  • מדדים אמיתיים לכל ערוץ. בסיס להחלטות שיווק חכמות

02 / ARCHITECTURE

ארכיטקטורת המערכת

עקרונות תכנון

/ 01

מודולריות

הוספת מקור או יעד חדש אינה דורשת בנייה מחדש. רק חיבור מודול נוסף ל-Hub הקיים.

/ 02

שליטה פנימית

הקוד והתשתית בבעלות מלאה של דטוויז. אין תלות בספק חיצוני שיכול לשנות תמחור או להפסיק שירות.

/ 03

שקיפות וניטור

כל ליד שעובר במערכת מתועד. מקור, זמן, סטטוס עיבוד, וסטטוס בקומיגו.

/ 04

אבטחת מידע

אימות בקשות, סינון ספאם, אחסון מאובטח. פרטי גישה לקומיגו שמורים בצד שרת בלבד.

04 / ROADMAP

שלבי הפרויקט

הפרויקט מחולק לשלושה שלבים. מ-Prototype מקומי דרך אישור אבטחת מידע ועד עליה לאוויר.

01
BUILD

פיתוח Prototype מקומי

בניית כל התשתית במחשב הפרטי, כולל שרת ביניים, דשבורד מעוצב, Mock של ה-API של קומיגו, ובדיקות end-to-end. הפרויקט יהיה מוכן להדגמה חיה ללא חיבור לשרתי החברה.

Next.js React RTL + EN Mock API
02
REVIEW

סקירת מנכ״ל ואבטחת מידע

הצגת ה-Prototype למנכ״ל, אישור עקרוני, ולאחר מכן העברה לצוות אבטחת המידע של דטוויז לבדיקה ולאישור התשתית, מבנה האימות, ושמירת המידע.

Demo Security Code Review
03
LAUNCH

חיבור לסביבת ייצור

קבלת API מאוריגמי/קומיגו, חיבור ה-Webhook ב-Wix לשרת הייצור, העברה לסביבת החברה, בדיקות סופיות, והשקה הדרגתית.

Comigo API Wix Webhook Soft Launch
הערה לגבי לוח זמנים: שלב 1 בלתי תלוי בגורמים חיצוניים ויכול להתחיל מיידית. שלב 3 תלוי בקבלת API מקומיגו. לכן ההמלצה היא לפתוח במקביל את ערוץ התקשורת עם אוריגמי במהלך שלב 1.
05 / PRD STRUCTURE

מבנה ה-PRD המלא

המסמך הנוכחי הוא תקציר מנהלים לאישור עקרוני. בכפוף לאישור, יוכן PRD מלא בן 11 פרקים שיהווה את ה-source of truth לפיתוח, לעיצוב ולבדיקות.

01

Executive Summary

תקציר מנהלים, מטרת הפרויקט, ערך עסקי צפוי, וקריאה לפעולה.

נכלל
02

Problem Statement

תיאור מפורט של הבעיה, השלכותיה התפעוליות, וההיקף הכמותי של ההפסד הקיים.

נכלל
03

Goals & Success Metrics

הגדרת יעדים מדידים, KPIs תפעוליים ועסקיים, ושיטות מדידה.

נכלל
04

User Personas

פרסונות המשתמשים: מנהל תמיכת לקוחות, נציגי מכירות, מנכ״ל. צרכים, מטרות, ונקודות כאב לכל אחד.

בעתיד
05

User Stories & Flows

זרימות משתמש מפורטות מ"לקוח ממלא טופס" ועד "נציג רואה את הליד בדשבורד".

06

Functional Requirements

כל הפיצ׳רים בפירוט: קליטת לידים, סינון, תיוג, ניתוב, התראות, דשבורד, דוחות, הרשאות.

בעתיד

Non-Functional Requirements

דרישות אבטחה, ביצועים, זמינות, scalability, שפות תמיכה, ונגישות.

Technical Architecture

סטאק טכנולוגי, מבנה השרת, מבנה בסיס הנתונים, אבטחה, ניהול סודות, deployment.

09

UI/UX Design & Mockups

מוקאפים מלאים של כל המסכים, design system, אנימציות ומיקרו-אינטראקציות.

בעתיד
10

Roadmap & Milestones

תכנון מפורט של שלבי הפיתוח, אבני דרך, ולוח זמנים מקצה לקצה.

נכלל
11

Risks & Open Questions

זיהוי סיכונים, אסטרטגיות הפחתה, ושאלות פתוחות שדורשות החלטה לפני תחילת הפיתוח.
